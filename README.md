# Emergency Triage Queue Simulator

## Project Description
This project implements an emergency triage queue simulator for a casualty ward. It evaluates and compares the performance of an indexed binary min-heap (Structure A) and a binary heap with lazy invalidation (Structure B) against a baseline unsorted array oracle. The application replays 30 simulated days of patient arrivals, severity revisions, departures, and treatments under both linear aging and step-wise escalation policies[cite: 6].

## Build Instructions
To compile the core structures, application simulator, differential tests, and benchmarks[cite: 2], run the following command from the repository root:
`make all`

## Execution Command
Use this single command to sequentially run the differential tests, the triage application simulator, and every performance benchmark, including D6[cite: 2]:
`make run_all`

## D6 Analyst Benchmark
Run `make run_d6` (or compile `bench/run_d6.cpp` with C++17 and run it from the repository root). It requires at least five repetitions and runs both aging policies at revision shares from 0% to 90%, then a separate one-million-patient scale check. It writes raw measurements and mean/sample-standard-deviation summaries under `results/`, plus the D6 report and SVG figures under `docs/derivations/`.

The report and figures are regenerated by `bench/analyze_d6.py`. Python 3 is needed for the summaries and SVG output; install ReportLab (`py -3 -m pip install reportlab`) if you also want the script to regenerate the PDF. The checked-in D6 PDF is the report for the committed measurements.
